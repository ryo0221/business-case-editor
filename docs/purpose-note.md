# 目的と代表操作

新規事業の企画の工程6で、出所の分かる前提から10年・年次の収支を作り、基本・楽観・悲観の3シナリオのNPV・IRR・回収年を比較して、受け入れる版を人が判断する。集計は円を基準とし、THBの為替を明示した前提として扱う。各シナリオは少なくとも1つの前提を引用する。

## 利用者

### UR-01 企画リーダー・早川
シナリオと感応度を比べ、投資判断の材料にして、受け入れる版を決める。

### UR-02 アナリスト・石田
前提の値、単位、種類と出所を整え、収支を再計算し、結果を前提から引き直す。

### UR-03 経理・佐藤
前提と計算結果を経理の観点からたどって確かめ、収支モデルを承認する。

### UR-04 DX開発・中川
形式と取り込みを確認し、収支モデルを開いて保存・再読込できるようにする。

## 代表操作

### OP-01 前提を整える
石田は安定したFA-xxの前提を追加し、値・単位・実績／予測／仮定／計算の種類・出所や説明を直す。計算の前提には使用した前提とモデルの版をたどる根拠を持たせる。出所や必要な値が欠ける入力、重複するIDは受け付けず、シナリオから引用中の前提の削除は拒否する。

### OP-02 シナリオを作り比較する
石田は基本・楽観・悲観のSC-xxに前提を引用し、シナリオごとの上書き値を入れる。早川と佐藤は3シナリオの年次収支、NPV・IRR・回収年を比べる。存在しない前提への引用、前提の引用がないシナリオ、対象の範囲外の年数や割引率は拒否する。具体的な数値範囲は形式と操作の設計で定める。

### OP-03 再計算と感応度
石田は前提を変更して10年の売上・費用・設備投資・資金の動きと投資指標を再計算する。早川は対象前提をプラス・マイナスに動かしたときのNPVの変化を見て判断する。計算に必要な前提が欠ける場合や計算できない入力は結果を装わず拒否または理由を表示する。計算条件と丸めは後続の設計で定める。

### OP-04 根拠を確かめ版を受け入れる
佐藤と石田は結果の数字から使ったシナリオ、前提、出所にたどり、前提から引き直す。早川は比較結果を基に受け入れる版を決め、佐藤は経理の観点で承認する。根拠が欠ける、または引用先が存在しないモデルは受け入れ対象にしない。受け入れ済みの結果を保ち、後の変更と区別する。

### OP-05 戻す・提案を扱う
石田は編集をUndoで戻す。AIなど外部からの前提の値や出所の提案は、人が確認して採用または破棄でき、採用後もUndoで戻せる。対象が変更済みなど提案の前提が成り立たない場合や不正な値は採用を拒否し、元の内容を保つ。

### OP-06 読み取り・保存と取り込み
佐藤は読み取り専用で開いて結果と根拠を確認し、中川は対象形式のモデルを取り込み、保存・再読込して内容を確認する。読み取り専用では編集、提案の採用、Undoなど内容を変える操作を拒否する。不正な形式や範囲外の内容の取り込みは拒否し、現在のモデルを保つ。

## 新しい Editor が要る理由

既存の表Editorはセルを表示・編集できても、前提の種類と出所、シナリオから前提への引用、引用中の削除禁止を収支モデルの規則として一体で扱えない。表示切り替えだけでは3シナリオの上書き、結果から前提への追跡、受け入れた版の保持は得られない。既存の計算基盤は活用するが、計算だけでは前提の根拠、人による提案の採否、年次収支と投資指標の比較を一連の操作として保証できない。

## 扱わないこと

### EX-01 月次計画
初版は10年・年次に限り、月次の入力、計算、表示は扱わない。

### EX-02 詳細な税務計算
税法ごとの控除や申告などの詳細な税務計算は扱わない。必要な税に関する集約値は根拠のある前提として扱う。

### EX-03 複数通貨の会計
円を集計基準としTHBの換算率は前提にするが、複数通貨の帳簿や通貨別決算は扱わない。

### EX-04 複数人の同時編集
同時編集やリアルタイムの競合統合は扱わない。承認は人が行うが、共同編集の機能とは別とする。
